# 第 0 步：组队与节奏

> 商赛里大多数团队冲突来自两件事：行动不清晰，行动不匹配自身。

## 一、行动不清晰

1. **讨论流于形式。**对选题内容不了解，一味套框架，产出时反复修改，「当时不是说 xxx 吗，怎么又改」。所以每个人先读完材料，再开会。
2. **主线混乱。**把每个板块当成独立的，缺全局衔接，前后逻辑冲突。所以先出一份全组共用的框架和核心逻辑段，再按章节分给具体的人。

## 二、行动不匹配自身

1. **刻板设任务。**比如一周一次会。有人喜欢每天复盘，有人三天一次，有人两周一次。不匹配就会出现迟到、缺席、开会不说话。不要觉得自己能克服，漫长的赛程里会渐渐克服不了。按成员能适应的最大程度设节奏。
2. **高估自己。**一开始觉得能做，做着做着发现做不了。做自己擅长 / 喜欢的板块，长板拼长板。做不了立刻说，换方案，减少沉没成本。

## 三、怎么分工

- **按长板和将来想做的岗位分**（以终为始）：想做产品的管产品设计，想做咨询的管框架和竞争分析，想做用户研究的管访谈。比赛结束时，每个人都能在简历上讲清自己负责的那块。
- **按交付物和评分结构分**：限时赛常见切法是一人管主线和创新点、一人管财务和风险、其余人管内容和视觉。有视频或路演时，把要回答的问题分到每个人。
- **必须有一个人对最终主线负责。**只能一个。

## 四、两个截止点和倒推

- 各部分**内容截止**在前，**成品制作截止**在后，中间留整合时间。开工前统一字体和格式。
- 用户没给日期时，默认倒推：
  - M1 启动 + 拆题：开工后第 3 天（限时赛：开场 30 分钟内）
  - M2 框架初稿：全程 1/3 处，必答清单的每一条都有了位置和关键数据点
  - M3 方案成型：全程 2/3 处，方案、财务、可行性基本定稿
  - M4 锁定：截止前 3 天，只改视觉和讲稿，留缓冲
- 到 M2 必答项还没框进去，要警觉；M3 之后还有大量「锦上添花」没做，只能割舍。

## 五、范围优先级（MoSCoW）

- **Must**：缺了评委会否定整个方案。判断方法：缺了它，评委会不会因此否定方案？必答清单上的每一条都是 Must。
- **Should**：显著提高质量但不是根基。
- **Could**：锦上添花。
- **Won't**：本次不做。题目没问的，写进这一栏，防止团队跑题。

## 六、从第一天开始记录团队过程

很多比赛要讲团队故事（团队素质视频、协作报告、答辩里问「你们遇到过什么困难」）。到最后再回忆，故事拿不出来。从组队起就记：分歧、怎么决策的、分工怎么调整的、学了什么陌生领域。

## 七、迭代节奏

- 先出短版跑通逻辑，再扩成长版。
- 每一版末尾放一页编号改动清单：改了什么、回应了哪条意见、还缺什么。
- 收到反馈后逐条补实质内容，不只改措辞；反馈和自己判断冲突时，先回头核对原稿再改。

## 八、AI 带这一步的动作

1. 先查 [02_题型路由.md](02_题型路由.md) 第三节第 0 步这道题的裁剪（例如按讲稿段落分工、每人都要发言、团队单独计分时加重）。
2. **先问，再出表。**问：几个人、各自擅长什么、能接受多久同步一次、谁管主线。学生回答之前，不给预填好的分工表，不替团队决定谁做什么。一次只问没答过的项。
3. 核对资格（人数、年龄、同校、学历、是否要注册）。
4. 学生答完后，输出一张表：分工、同步频率、主线负责人、四个里程碑日期。
5. 「以终为始按岗位分工」「团队过程日志」这类建议，只在和本题评分有关（例如团队单独计分、要讲团队故事）时提，否则不提。
