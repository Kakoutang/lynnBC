# 第 3–4 步：问题 / 痛点，以及题目关心的那群人

> 有些方案创意很好、也用了前沿科技，就是没得奖。原因往往是痛点找得不准。

## 一、先看题目

- **题目已经给了痛点或问题**（策略单写了品牌痛点、案例点明了挑战）：直接用题面的说法，在它基础上深挖，不另造。
- **题目问的不是用户**（投资、选市场、政策、供应链）：这一步换成「关键问题 / 根因 / 投资逻辑」，见本文第六节。
- **题目开放或自选**：痛点就是题目本身，做最重。

## 二、为什么痛点决定方案质量

所有咨询、创业、产品本质都在做一件事：**识别 → 量化 → 解决痛点。**痛点就是商业机会。idea 成不成，看痛点找得准不准，不看产品多炫、理念多超前。

跑步时你需要运动鞋，不是名牌高跟鞋。**产品提供的价值和用户要完成的任务不一致时，再高端的定位也无法转化为购买。**

发现痛点不靠灵光一现，靠把流程拆到足够细。

## 三、痛点的定义和五个来源

**痛点 = 阻碍客户（企业或用户）达成目标的关键摩擦点 / 低效 / 价值流失。**

| 来源 | 长什么样 |
|---|---|
| 客户体验 | 决策路径被打断：信息太主观没法判断、线下体验混乱、交付环节出错。用户不愿意跨多个渠道完成一件事，不愿意在不同信息源之间反复对比，不愿意在关键节点等太久 |
| 运营流程 | 内部看起来合理，用户侧重复冗余：系统不打通重复填信息、物流不透明、报名流程复杂 |
| 战略定位 | 价值和用户的真实任务错配：企业讲复杂度和艺术表达，用户只想要一个不出错的选择 |
| 组织结构 | 线上线下、各团队责任不清，用户体验割裂，价值在内部被消耗 |
| 技术系统 | 没记录用户偏好和历史，每次都要重新选，企业失去复购机会 |

把这五个来源放在一条完整的用户旅程上看，价值是在一个个细小的摩擦里流失的。

## 四、怎么找（三种方法结合）

1. **翻评论区**：电商、官网、第三方渠道，重点看低分评论，它会具体描述问题发生在哪个环节。看高频重复的，不被个别极端案例带偏。
2. **看社媒**：重点看评论区有大量讨论和分歧的帖子；区分种草内容和真实使用反馈，优先看用户讲自己决策过程和踩坑的帖子。
3. **访谈**：和真实用户一对一聊最近一次的完整经历：为什么想要、怎么筛选、最终怎么选、用后感受。**重点不是问他们喜欢什么，是让他们复盘哪里花了很多时间、哪里不确定、哪里后悔。**每个回答都追问一句「为什么」，要原因，不要表面答案。

访谈对象怎么选：第 3 步之前先写一个初步的目标人群假设，按它选访谈对象；第 4 步再根据访谈修正。

还可以把产业链上每个角色过一遍（终端用户、一线从业者、渠道、品牌方），各写各自视角的痛点，再找交叉点。

把研报里的宏观结论翻译成具体场景：先拿自己或身边人的真实经历拆出购买路径和决策因素，再去研报里找对应数据和案例印证。研报一句「情绪经济」带过的地方，你要具体到「什么人、在什么场景、付款那一刻买的是什么」。（学生本人不是这个品类的消费者时，例如 B2B、医疗、金融机构，这个方法走不通，改用访谈和行业资料。）

## 五、从材料到痛点

1. **归类**：功能类、使用体验类、心理情感类（亲和图法）。
2. **排序**：频率 × 严重性，选出 1–2 个最有影响力的。
3. **确认**：用问卷看是否普遍；有条件做最小原型。
4. **算出来或比出来**：用需求量 × 行业配比得出理论需求再和供给比；从收入推出可接受价格再和市场价比；或者把对象的关键指标和行业平均、标杆并排放。差距就是痛点，算式可以直接放在页面上。
5. **挑有商业价值的**：是否普遍、解决它能不能增强竞争力或打开新市场；竞品是否已经解决了，没解决才是机会。
6. **写成一句话**：「我们的用户在 ___ 环节，因为 ___，所以 ___」，或「用户需要 X，但市场上缺 Y」。痛点之后必须接方案。

痛点证据：定性的放访谈原话，定量的放问卷图表，页面写清样本量和方法。「我觉得用户需要」的问题，评审会打回。（限时赛和封闭赛不能做一手调研时，证据来自案例数据和二手资料，不强求访谈。）

开篇可以用一句话重新定义问题：表面现象只是症状，真正的问题是更深一层的结构性缺口；再加上「不改会被谁吃掉」的外部威胁，制造紧迫感。

## 六、题目问的不是用户时

| 题型 | 这一步换成 |
|---|---|
| 战略咨询 / 限时案例 | 根因和障碍诊断：从案例材料里提炼关键问题；题目问障碍才单列，否则压成一页「现状与关键洞察」 |
| 投资金融 | 投资逻辑、关键驱动因素、与市场一致预期不同的观点。一手调研（消费者访谈、门店走访）只在规则允许时做，而且只用来验证某个关键驱动或差异化观点，不是为了「看消费者喜不喜欢」；规则禁止接触标的公司时，也不接触其员工 |
| 政策 / 经济 | 问题界定：题目给的经济问题本身 |
| 市场调查 | 研究问题：结论必须回到这个问题上 |

## 七、第 4 步：题目关心的那群人

**只在题目点名人群或客户时做重。**否则压成一句目标人群，或换成题目真正关心的对象：

| 题目关心 | 做什么 |
|---|---|
| 终端用户（营销、创业） | 每类人写人口特征、行为特征、文化背景，再写和方案直接相关的痛点。不写成一串形容词。可以给两三个具名人物。目标用「用户嘴里说得出的话」写，比如「让我下次买的时候第一个想到它」，不写「提升品牌知名度」 |
| B2B 客户 | 决策链：使用者、决策者、付款者、影响者各自要什么；采购流程和周期。题目对应专业或 B 端业务时，方案要同时照顾 B 端从业者和终端客户，问一句「从业者买不买单」 |
| 受益人（公益、ESG） | 受益人需求评估、受益人数口径；企业 ESG 题换成利益相关方或实质性分析 |
| 市场 / 国家 / 业务段（战略） | 用筛选矩阵排优先级，不做用户画像 |
| 调查对象（市调） | 抽样设计、样本量、样本描述，这一步做最重 |
| 受影响人群（政策） | 分配效应：谁受益、谁受损 |

**包容性分两层**（评分有包容维度时）：战略上可以聚焦一个核心人群；战术上的产品、价格、营销语言和体验设计不能人为排斥任何群体（价格梯度、无障碍、去刻板印象、清晰标注）。

**用户规模**：画像页的人群规模要能接到第 7 步收入预测的用户基数（人群数量 × 渗透率）。多个客群时，说清先打哪个、为什么。

## 八、教练的边界

- 问题陈述写出来之前，只追问「为什么会这样」。可以给追问的**类别**（买不到 / 买不起 / 不信任 / 不知道），**不把类别连到某种方案或商业模式上**，不预选 SDG。
- 审选题时指出「太宽 / 太泛 / 和题目对不上」，不替学生给出具体切口。具体切口要从学生自己的材料里来。

## 九、AI 带这一步的动作

1. 先问：题目给痛点了吗？题目关心的是用户、客户、受益人、市场，还是别的？
2. 问学生手上有什么材料。什么都没有，就派任务：几个平台各找若干条低分或有争议的内容，做几个访谈（限时赛跳过访谈）。
3. 拿到材料后，按五个来源归类，按频率 × 严重性排序，输出一张表。
4. 让学生说出「我们的用户在 ___ 环节，因为 ___，所以 ___」。说不出来，回到材料。
