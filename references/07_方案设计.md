# 第 6 步：方案

> 关注用户价值，超越用户需求。马车时代问用户要什么，他们只会说「一匹更快的马」。超越需求，首先要超越你自己的认知边界。

## 一、方案的形式由题目决定

| 题目要的结论 | 方案长什么样 |
|---|---|
| 新产品 / 新体验（营销、创新） | 名字 + 一句话概念 + 核心功能 + 用户旅程；题目点名科技时加「技术怎样服务痛点」；评分有可持续、包容时加具体机制 |
| 广告 / 传播策划（命题策略单） | 洞察 → 策略推导 → 创意与核心内容 → 传播排期与渠道 → 预算（不超过策略单上限）；策略单点名投入产出比时才测算。主题、痛点、人群用策略单给定的 |
| 一个选择（战略） | 推荐 + 2–4 个举措 + 分阶段路线图，每个举措回扣题目的量化目标 |
| 限时案例的建议 | 2–3 个备选 → 用题面约束定标准做打分矩阵 → 1 个推荐，少而准 |
| 商业计划 | 创新点归类（产品、工艺、服务、商业模式）+ 原型、试点、专利等实证 |
| 投资动作 | 建议与估值、交易结构、价值创造举措 |
| 社会企业 / ESG 项目 | 按题目（社会企业、整改项目、金融工具、真实经营） |
| 调查 | 调查方案和实施（方法、问卷或访谈、质量控制、数据处理）+ 可操作的建议 |
| 政策 / 立场 | 明确的决定或立场 + 反驳一个可信的替代方案 |

方案里每一项都要对应必答清单的一行。

## 二、先有需求，再选科技

- 每用一项技术，都说清它解决哪个具体痛点、降低了用户哪种成本。评委不会因为技术新加分，技术名词越多越像炫技。
- **题目点名科技时**，科技必须有，而且必须从痛点里推出来；**题目没点名**，不硬塞、不单开一章。
- 数据收集、模型训练这类实现细节不是方案内容，篇幅留给「谁买单、怎么规模化」。
- 找不到来源的精确技术参数一律删掉；成本不可控的体验硬件，降级为成熟技术。
- 技术方案写成可以横向复用的平台能力，不停在单点噱头上；涉及用户数据，写出数据闭环和隐私合规。

## 三、创新按「解决了什么痛点」来评

- 每个功能或举措都要回指一条具体的痛点或根因。痛点页和方案页可以做成一一对应的两列。
- 核心功能控制在评委记得住的几个。
- 写到能直接执行的颗粒度：具体平台、活动名、价格、频次。每条战术写成「做什么 + 通过什么机制 + 达到什么效果」。框架和理论只当骨架，不拿来当结论；用自创的具体机制替代 4P 式的通用清单。

## 四、方案三感（产品类方案的自检）

| 感 | 评委的问题 | 怎么建立 |
|---|---|---|
| 安全感 | 这个东西真的能做出来吗？数据是真的吗？技术成熟吗？ | 来自对甲方现有资源的理解与延展，不是凭空创造。过度理想化会被迅速识别 |
| 价值感 | 如果我是用户，我愿意为这个付钱吗？ | 解决真实痛点；改变用户和产品的关系，把单次购买变成长期关系 |
| 向往感 | 这个方案成功了，行业会变成什么样？ | 描绘未来场景；只「解决了一个问题」最多及格 |

判断价值感：产品价值 = 产品力 ÷ 产品价格 × 产品质量。

（战略、投资、政策题不用三感，换成：建议是否回答了题目、是否可行、是否有取舍。）

## 五、做选择题时

选国家、城市、市场、方案时：
- 只给一个推荐，专门写为什么不选其他看起来也合理的候选，每个被排除的一条具体理由。
- 选出的结论必须接住前面列过的痛点或问题，不另起一套理由。
- 可以用打分卡：候选 × 维度 × 分值，每个维度的评分规则和数据来源写在表下。页数少时用漏斗：大盘 → 细分 → 用一个指标筛出候选 → 候选逐一对比。
- 战略题先列至少两个极端方案和一个组合方案，逐个评估利弊、可行性和资源约束，再说明为什么选这个；先说清最直观的极端方案为什么不现实。

## 六、竞争与对标

- 竞品分析不停在对比表上：先摆出已有产品和竞品已经在做的同类服务，点出甲方的位置，再写差异化。
- 竞争结论落在对手结构上无法复制的那一维。可以用一句对照式定位收尾：「对手靠 X，我们靠 Y」。
- 用对标证明可行：找一个背景和定位相近、已经走通这条路的对象；参考案例写成有具体动作和前后数字的小故事。
- 没有说服力的竞品删掉。

## 七、可持续、社会价值、ESG（题目要求时）

- 长在方案或机制本身，不要结尾补一句。至少落地一项可执行的机制，写清激励和运营方式；最好设计成用户愿意参与的行为。
- ESG 页不照搬甲方 CSR 原文，不塞和本公司无关的行业常识。按甲方自己的使命框架归类，写清自己方案里哪个机制给谁带来什么作用。
- 不只写正面：列出方案带来的负面影响或成本，各配一条对策。
- 能换算成商业回报的就换算（流失率、获客成本、复购、溢价）。题目本身就是「做了 ESG 业绩没涨」时，必须正面回应。
- 公益或社会议题类方案，要有让项目自己赚钱、再养活公益目标的闭环；只靠外部输血会被判不可持续。

## 八、其他通用规则

- **名字与一句话概念**（产品和营销类）：用「针对谁，推出什么，解决什么问题」的句式。
- **风险与对策**：逐条对应，每条对策都能执行；讨论自己证据的局限和方案的副作用。
- **可判定、可追踪**：把口号式承诺改成有编号、时限、负责人、指标的机制。
- **整套而不是几个点子**：写成环环相扣的整套方案。学生团队自己经营的项目，定位为轻资产的资源整合者，差异化放在大玩家不占优势的地方。（给大企业出主意的咨询题不受此限，重资产选项也可能是对的。）
- **进入新市场**：不照搬原市场打法，先借目标市场已流行的内容打下核心客群，再适配多元需求。
- **合规**：涉及功效宣称、金融牌照、医疗、个人信息、广告用语的方案，写一句合规考虑。
- **撞题检查**：方案不和甲方已上市的产品、往届获奖作品、公开破题内容雷同。

## 九、AI 带这一步的动作

1. 先确认题目要的是哪种结论（上表）。
2. 让学生用一句话说出方案；再列出每个功能 / 举措对应哪条痛点或必答项。对应不上的删。
3. 逐个技术名词追问：解决谁的什么问题？不用它行不行？
4. 产品类过一遍三感；选择类检查排除理由；ESG 类检查负面与对策。
