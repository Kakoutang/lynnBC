# 常见失败模式

按在辅导材料里出现的频率排。每一步结束时可以拿来对照。

| # | 失败 | 解法 |
|---|---|---|
| 1 | **数字没有依据或是编造的**：没有推导的增长和回报、精确到小数的「预测」、「已达成合作意向」、无来源的技术参数、自编的百分比、编造的参考文献、自评打分表没有口径 | 粗估写明假设；找不到来源就删；增长说清和什么基线比；打分表每格写理由；参考文献逐条核实 |
| 2 | **数字前后矛盾**：同一指标在不同页或讲稿里不一样；算式自相矛盾；文字和表格不一致；比较词和数字方向相反；单位币种错；清单标题条数和内容不符 | 一张底表出所有数；提交前跨 PPT、讲稿、backup 核对；多人分写前统一口径；数字不自洽的整页宁可删 |
| 3 | **残留**：模板文字、AI 图片乱码、内部备注、占位符、拼写错误 | 提交前专门做一轮清理和拼写校对 |
| 4 | **空泛**：营销或战略写成口号、4P 清单、放之四海皆准的行动，评委说太理论 | 写到平台、活动名、价格、频次；每条「做什么 + 什么机制 + 什么效果」；用自创机制替代清单 |
| 5 | **技术先行或堆砌**：一套 AI、AR、大数据回答所有问题；把实现细节当方案；通用热门技术当独特卖点 | 先需求后科技；每项技术说清解决哪个痛点；卖点落在甲方已有的资产上；篇幅留给谁买单、怎么规模化 |
| 6 | **AI 稿的通病**：照抄评分表做目录或按维度逐条罗列；自称「完美契合」；空泛的励志文字；框架堆砌没有证据 | AI 稿只取骨架；评分表只当自查清单；用真实证据重做问题定义 |
| 7 | **ESG 写成公关稿**：照搬甲方 CSR 原文、只写正面、塞无关的行业常识、硬套术语 | 按甲方价值观归类并写清自己的机制起什么作用；列负面与对策；换算成商业回报 |
| 8 | **文字堆砌**：研究笔记式、罗列式原稿，看不出商业逻辑 | 压成编号模块和流程图，标题改结论句，细节进讲稿和 backup |
| 9 | **讲稿和页面对不上**：润色版堆形容词、缺章节、说法不一致、把读图的工作推给观众 | 逐页对应、平实口语、数字一致、自己讲解每张图 |
| 10 | **目标人群写成形容词堆砌**，几类人重叠，人群太窄又没有包容论述 | 写人口、行为、文化和直接相关的痛点；战略聚焦一群，战术不排斥任何人 |
| 11 | **定价只有区间或方法**，只列费用科目没有逻辑 | 每一档给数字，成本、价值、竞争三方面讲依据，设计梯度和锚定 |
| 12 | **痛点证据只有桌面数据**，访谈只拿到表面答案 | 访谈追问为什么，问卷确认是否普遍；市场研究放在方案之前 |
| 13 | **漏掉第二类客户或关键参与方**：只顾终端用户，缺 B 端；漏了控制点、竞争、监管 | 产业链逐个角色过一遍；定稿前自查评委必问的几件事 |
| 14 | **凑数的图、空壳页**，必答页拖到最后还是空白 | 每张图配 takeaway，连不上就删；空壳页宁删不交；必答页最先排期 |
| 15 | **漏掉题面点名的元素**，压缩篇幅时误删必答段落 | 必答清单逐条落点，压缩后回头核对 |
| 16 | **只列问题不给解法**，风险页对策写「还没想好」 | 痛点后必须接方案；风险和对策逐条对应 |
| 17 | **分析工具用错或写成套话**：五力讲成自己的优势，SWOT 的机会写「团队年轻」 | 框架用本案的数字和判断填，用错不如不用 |
| 18 | **结论强度超过证据** | 措辞和证据匹配，写明局限 |
| 19 | **进入新市场照搬原市场打法** | 两步本地化，配真实对标 |
| 20 | **让 AI 绕过思考直接出 idea 或定价**，AI 只给公式不算结果 | idea、定价、判断不交给 AI；必须真算 |
| 21 | **前后叙事矛盾**，各板块各自独立 | 守住一条故事线 |
| 22 | **提议了企业已有的东西** | 先查现状，说清已有机制为什么没起作用 |
| 23 | **团队协作失败**：讨论流于形式、反复推翻、会议节奏刻板、高估能力 | 先读材料再开会，按长板分工，节奏贴合成员，做不了立刻说 |
| 24 | **答辩时直接说「不了解」，或用大词给评委留追问口子**，把自己当被审判的人 | 先讲已知事实再承认不足；用具体事实替代大词 |
| 25 | **使用场景太散**，撑不起商业闭环 | 场景服务商业闭环，删掉无关场景 |
