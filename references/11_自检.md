# 第 10 步：提交前自检

模拟评委。学生把方案（文字、PPT 大纲或内容）贴进来，按下面的顺序检查。

## 一、一句话测试

评委 5 秒内明白、10 秒内喜欢、30 秒内相信：
1. 用一句话总结方案，不懂行的人能不能秒懂？
2. 核心创新或核心建议能不能用一个场景或一个数字直观呈现？
3. 是不是可以落地执行，不只是一个概念？

## 二、必答清单逐条打勾

拿第 1 步的编号必答清单，逐条找方案里对应的页 / 段：
- 每条都有答案吗？
- 题目给的量化目标，有没有用数字证明能达到？
- 被禁止的、题目明说不用做的，有没有碰？
- 没被问到的内容，有没有删掉？

## 三、按题目自己的评分表打分

- 用**这道题的评分表**，不用别的比赛的。没有评分表就按必答清单等权打。
- 每个维度给分 + 一句理由，理由必须指向方案里的原句。
- 打分要严：3 分是「有但不够具体」，满分必须能指出原句作为证据。
- 有甲方的题，加做换甲方测试：换成最像的和最不像的竞争对手，改动少于三处，「创新」或「匹配」维度封顶在中档。
- 列出所有技术名词，各自解决什么问题；答不出的，可行性扣分。
- 判断「市面已有同类」时，只引用说得出名字和来源的产品，拿不准写「待查证」。

## 四、追溯链

痛点 / 问题 → 方案的功能或举措 → KPI → 财务，逐条能连上吗？断在哪里就是评委追问的地方。

## 五、一致性

- 同一个数字在 PPT、讲稿、报告、backup 里一致。
- 比较词和数字方向一致；单位和币种全文统一，和题面一致。
- 文字结论和表格数字一致。
- 多人分写时汇总前统一口径。
- 品牌名、人名拼写前后一致；语言统一。

## 六、红线与技术检查

- 页数（含不含封面附录）、字数、时长、文件大小和格式、命名、官方模板。
- 匿名：有没有出现学校和姓名。
- 数据边界：有没有用到不允许的数据；所有图表是否标了来源；参考文献逐条核实存在。
- AI 使用：是否需要披露；查重要求。
- 版权：甲方 logo 和商标的使用是否允许；网络图片和 AI 图片是否允许。
- 文件：导出后排版没走样、字体嵌入、超链接、视频能播放。
- 清理残留：模板占位文字、旧的对象名、内部备注、AI 图片里的乱码、水印。最后做一遍拼写校对。
- 压缩篇幅后，回头核对每一条必答项还在。

## 七、冷读

请一个队外的人只看页面、不听讲解，看他能不能说出主线。说不出，标题和结构还要改。

## 八、输出格式

```
## 自检结果（模拟评委）

一句话测试：通过 / 不通过（原因）
必答清单：共 N 条，已答 M 条；缺：第 __ 条、第 __ 条
禁区 / 不用做的：有没有碰

| 维度（本题评分表） | 分 | 一句话理由（指向原句） |
|---|---|---|
| … | /… | |
| 合计 | /… | |

换甲方测试（如适用）：改 N 处 → 通过 / 不通过
技术名词：X 个，其中 Y 个说不清解决什么问题
追溯链：断在 ___
一致性 / 红线：发现的问题

## 最弱的一项
___ 维度最弱，因为 ___。
```

指出最弱的一项和原因，说清评委会在哪里追问，以及改进的方向；具体改法由学生动手完成。不给逐条改写好的文字。
